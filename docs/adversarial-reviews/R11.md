## Primera revisión — FAIL

El candidato inicial superó el gate autoritativo, pero recibió `FAIL` por un
hallazgo documental de severidad media. La especificación decía que al cambiar
el nonce dependían de éste la cardinalidad y `Λ`. El nonce se codifica como
`uint64` fijo: para el mismo payload ambos records tienen la misma longitud y,
por diseño, cardinalidad y firma de longitud coinciden.

La reproducción del revisor obtuvo:

```text
cardinality igual:       True
length_signature igual:  True
anchor igual:            False
parameters igual:        False
```

No se encontró un bypass del algoritmo PoW. El defecto era una afirmación más
fuerte que la implementación y que el modelo formal.

## Corrección

El commit final precisa que el nonce entra antes de toda preparación, pero que
cardinalidad y `Λ` pueden coincidir por el ancho fijo. El ancla cambia y, a
través de `A/J`, cambian parámetros, `S0`, rondas y digest.

La regresión versionada comprueba explícitamente, para nonces 0 y 1:

- cardinalidad idéntica;
- firma de longitud idéntica;
- ancla distinta;
- parámetros derivados distintos;
- digest distinto.

Los blobs productivos de firma, KDF y PoW son idénticos entre el candidato
inicial y el final; la corrección no cambió el algoritmo.

## Evidencia adversaria final

### Firma

- Ed25519 autentica el wire exacto de `SigmaDigestV3.to_bytes()` junto a dominio,
  algoritmo e identidad de clave.
- Sustituciones de digest, key id, clave, firma, dominio y wire fueron rechazadas.
- La API de attestation no afirma binding del mensaje; la API full recomputa el
  input canónico completo.

### KDF

- Argon2id se ejecuta después de validar política; se comprobó con mock que una
  política rechazada no invoca el hash costoso.
- Parámetros, salt y suite quedan ligados al contexto v3.
- La clave final no tiene wire público, queda fuera de `repr` y rechaza pickle.
- Sólo Argon2id recibe la claim memory-hard; Sigma aporta binding y trabajo
  adicional acotado por `t_max <= 32` y `k_max <= 4`.

### PoW y `SPEC-V3-010`

- El nonce está en `SIG3POWI` antes de ancla, binding, derivación de parámetros,
  `S0` y rondas; no existe un camino de evaluación que lo añada después.
- Sustituir el nonce de una prueba hace fallar `verify_pow_v3`.
- Challenge, suite, predicado, dificultad, payload, nonce y digest se recomputan
  o autentican bajo dominios propios.
- No se realizan claims de VDF, verificación barata, constant-time, memory
  hardness de Sigma ni resistencia ASIC/GPU.

### Wires y downgrade

- Magic, versión, dominio, tags desconocidos/duplicados/desordenados, truncados
  y cross-wire entre firma, KDF y PoW fueron atacados y rechazados.
- El facade v3 expone R11 sin modificar el facade protegido de aplicaciones v2.
- El baseline v2.2 permaneció byte-idéntico y pasó su verificador autoritativo.

## Limitaciones

- Es una revisión de ingeniería, no una auditoría criptográfica independiente.
- No se reauditaron las primitivas externas Ed25519, Argon2id o SHA.
- No hubo benchmark de side channels ni análisis de hardware ASIC/GPU.
- El fuzzing se limitó a 200 mutaciones por codec.
- Las comprobaciones de invariantes PoW usan casos deterministas, no una prueba
  formal de ausencia de colisiones.
