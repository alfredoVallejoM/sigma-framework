# Auditoría inicial de Sigma Framework

Fecha: 2026-09-02  
Base: `9cf55bca43bea0da11994e820fcddaed0a8eb1c4`

## Resultado ejecutivo

El repositorio actual es un prototipo experimental v1, no una librería
criptográfica apta para producción. La reconstrucción v2 descrita en el plan
maestro está justificada y debe ser incompatible de forma explícita.

Bloqueantes observados directamente:

1. `sigma/cli.py` contiene un `SyntaxError`; el paquete no supera
   `python -m compileall sigma`.
2. No existe una suite de tests (`pytest` recoge cero pruebas).
3. El digest de `SimultaneousStrategy` depende del número de CPU/workers y su
   ruta de archivo implementa una función distinta de la ruta en memoria.
4. `rounds` significa rondas criptográficas, número de workers o nada según el
   modo; además `rounds=0` queda sustituido por defaults mediante `rounds or N`.
5. `LightweightStrategy` retiene todas las hojas, por lo que su memoria es
   O(n), no O(1). Su árbol afirma RFC 6962 pero duplica nodos impares, que no es
   esa semántica.
6. `RealTimeStrategy` ignora contexto, tamaño y motor de rondas; el mensaje
   vacío devuelve 32 bytes cero y no existe `finalize()` explícito.
7. `ParanoidStrategy` comprime cuatro raíces de 512 bits a un ancla de 512 bits
   mediante `Psi`, perdiendo el compromiso ancho requerido por v2.
8. Los wrappers no registran IDs/tamaños, permiten algoritmos dependientes del
   host, no controlan finalización única y SHAKE no valida su anchura.
9. El framing v1 concatena campos sin un codec general ni parser, usa el nombre
   Python de la clase como identidad y no autentica suite/perfiles completos.
10. La salida v1 es un hex string sin versión, suite, parámetros ni estados
    consecutivos; no puede verificarse ni protegerse contra downgrade.
11. La metrología no conserva observaciones/manifiestos reproducibles y mezcla
    difusión, timing Python, estimaciones manuales y claims criptográficos.
12. README y docstrings afirman propiedades (constant-time, resistencia a
    side channels/ASIC, ortogonalidad, KDF/PoW y costes físicos) no demostradas.
13. El empaquetado declara Python 3.8+, pero no hay CI, dependencias opcionales,
    type checking, lint, build verification, SBOM ni política de release.

Comprobación diferencial puntual: con el mismo payload y cuatro workers,
`SimultaneousStrategy` produjo resultados distintos mediante `FileStream` y
`MemoryStream`. Esto confirma que INV-01/INV-08 fallan en v1 y que ese modo no
puede recibir vectores canónicos hasta ser reemplazado.

## Inventario y disposición

| Área v1 | Estado | Decisión |
|---|---|---|
| adapters/interfaces | reseteables, tamaño obligatorio en la práctica | conservar como legado; crear contrato incremental v2 |
| wrappers `hashlib` | mínimos y host-dependent | reemplazar por registro congelado |
| `PsiKernel` | compresor experimental sin análisis suficiente | mover después a `experimental`; no raíz de confianza |
| estrategias | cuatro funciones matemáticas incompatibles | convertir después en presets v2 |
| factory | mezcla semántica y defaults inseguros | mantener API v1; crear API v2 explícita |
| CLI | no compila | reparar baseline y versionar interfaz |
| metrología | exploratoria, no reproducible | retirar claims; reconstruir pipeline |
| documentación | sobreclaims y ejemplos KDF peligrosos | marcar v1 experimental y reescribir para v2 |

## Riesgos adicionales

- Validación insuficiente de enteros negativos o enormes permite resultados
  sorprendentes y potencial DoS.
- `FileStream` accede a detalles privados desde estrategias y asume archivos
  regulares/mapeables.
- Capturas amplias de `Exception` en CLI convierten fallos en salida parcial y
  no fijan un código de salida fiable.
- El código carece de vectores congelados: cualquier refactor puede alterar
  v1 sin detección.
- La denominación `signature` en RealTime confunde digest con firma digital.

## Conclusión

No se recomienda endurecer las estrategias v1 hasta convertirlas gradualmente
en v2: eso produciría incompatibilidad silenciosa. La ruta segura es congelar
vectores v1, añadir advertencias, construir `sigma.spec`/núcleo v2 por gates y
publicar suites versionadas nuevas.
